# EviREST

HTTP/REST APIの送信・検証と、テストエビデンスの出力ができるChrome拡張機能（Manifest V3）。
ビルド工程なし。外部ライブラリはExcel出力用の1つだけで、拡張機能に同梱している。

## できること

### リクエスト
- メソッド: GET / POST / PUT / PATCH / DELETE / HEAD / OPTIONS / QUERY
- 送信先のドメイン（ベースURL）とポート番号は環境ごとに設定し、URL欄にはパスだけを入力する。システム名・環境名・ベースURLはURL欄の左に常に表示される
- クエリ: 表形式で編集し、URL欄には `?page=${page}` の形で保持する。具体的な値はクエリ欄に保存し、送信時に展開する。行ごとに有効・無効を切り替えられる
- URL欄の下に、環境のベースURL・パラメータを反映した「送信予定URL」を表示する
- ヘッダー: 表形式で編集、行ごとに有効・無効を切り替えられる
- ボディ: JSON（整形ボタンあり）、テキスト、フォーム（urlencoded）
- 認証: Basic、Bearer トークン
- 送信の中止、`Ctrl / ⌘ + Enter` での送信
- CORSの制約を受けない（拡張機能の権限で送信するため、`localhost` や社内APIにもそのまま届く）

### レスポンス
- ステータス、応答時間、サイズ、ヘッダー一覧、送信した時点のURL
- JSONは自動で整形表示、画像はプレビュー表示
- ボディのコピー

### アサーション
- 対象: ステータスコード、ヘッダー、ボディ（テキスト）、JSONパス、応答時間
- 条件: 等しい / 等しくない / 含む / 存在する / より小さい / より大きい
- 送信のたびに自動で評価し、失敗があれば結果タブに切り替える

### パスパラメータ
- URLに `/users/${id}` または `/users/{id}` と入力すると、「パスパラメータ」タブに名前が自動で追加される
- 値は送信時にURLエンコードする。値に `${変数名}` を指定して環境変数も使える
- `${id}` はパスパラメータ欄の値を優先し、空欄・無効なら環境変数を使う。未展開のパラメータがURLに残る場合は送信を止める
- 設定はリクエストと一緒に保存し、JSONの `pathParams` にも含める

### システムと環境
- 「システム ＞ 環境 ＞ パッケージ ＞ サブパッケージ ＞ リクエスト」の階層で保存し、サイドバーにツリーで表示する
- 環境の作成と編集は別モーダル。各環境の「編集」から、選んだ環境だけを変更する
- サイドメニューの右端をドラッグして幅を調整できる。幅は保存し、ダブルクリックで標準幅に戻る
- 環境の編集画面で色を指定できる。サイドメニュー・ヘッダー・URL欄の環境表示に反映し、「標準色に戻す」で解除できる
- 環境はシステムごとに複数作れる（例: ローカル / 検証 / 本番）。環境ごとにベースURL、ポート番号、変数を持つ
- リクエストはシステムに1回保存すれば、そのシステムのすべての環境で使える。環境を選ぶだけで送信先が切り替わる
- URL、ヘッダー、ボディ、認証、アサーションの期待値で `${変数名}` が使える
- 未定義の変数が残ったまま送信すると通知する

### 保存と履歴
- リクエストに名前を付けてシステムに保存、上書き保存。保存画面でパッケージ・サブパッケージを指定できる（任意）。未指定は「未分類」に表示する
- 履歴は直近100件（リクエスト内容のみ。レスポンスは残さない）。履歴から開くと、送信時のシステムと環境に戻る
- システム（環境とリクエストを含む）をJSONでエクスポート・インポート。インポートは、ファイルを選ぶ方法と、JSONを貼り付ける方法の両方に対応
- インポートは `id` で突き合わせる。同じ `id` のシステム・環境・リクエストは更新し、ないものは追加する（削除はしない）
- cURLコマンドとしてコピー
- インポートファイルは手作業やAIでも作れる。書式は [docs/import-format.md](docs/import-format.md)
- サイドバー左下の「プロンプトを表示」で、AIにインポートファイルを作らせるプロンプトを表示し、その場で編集してコピーできる（編集内容は保存しない）

### 一括実行
- 画面上部の「選択した○件を実行」で、選択中の環境でチェックしたリクエストを順番に送信する
- 実行中・終了後は「一括実行結果」タブを自動で開く
- サイドメニューのチェックは一括実行の対象選択用。実行結果はすべて「エビデンス」タブに保存する。「一括実行の対象をすべて選択」で全選択・全解除できる。設定は全環境で共有する
- 結果欄の「HTMLで開く」で別タブにレポートを表示し、「Excel出力」でファイル保存できる
- レポートには各実行の送信URL・ステータス・アサーション・ヘッダー・ボディを含める。認証情報のヘッダー値は伏せる
- 中止した場合も、それまでの結果を出力できる。一括実行の結果は画面を閉じると消える

### テストエビデンス
- 実行結果に、テストケースID・確認内容・実施者・備考を付けて記録する
- アサーション結果から OK / NG を自動判定する
- 一覧表と1件ごとの詳細をまとめたHTMLレポートを別タブで開く。保存・印刷はブラウザの機能を使う。印刷すると1件1ページになる
- 同じ内容をExcel（`.xlsx`）でも出力できる。1枚目が一覧、2枚目以降がエビデンス1件につき1シート
- Authorization、Cookie、トークン類のヘッダー値を伏せ字にして出力できる（HTML・Excel共通）

### その他
- アカウント登録なし、クラウド同期なし。データはブラウザ内にだけ保存する
- ビルド工程なし。外部ライブラリは [write-excel-file](https://www.npmjs.com/package/write-excel-file)（Excel出力用）だけ

## できないこと

Postman、Insomnia、Talend API Tester、Thunder Client、Hoppscotch などの競合の多くが対応していて、EviREST が対応していないもの。

### リクエスト
- ファイルアップロード（multipart/form-data）、バイナリのボディ
- GraphQL、WebSocket、gRPC、Server-Sent Events、SOAP
- OAuth 2.0、Digest、AWS署名、NTLM などの認証（APIキーはヘッダーに手で書けば送れる）
- Cookieの自動保存と送信（Cookieは常に送らない設定で送信している）
- リダイレクトを追わない設定、途中のリダイレクト応答の確認（常に最終応答まで追う）
- タイムアウト時間の指定
- プロキシ、クライアント証明書（mTLS）、自己署名証明書の検証スキップ
- `Cookie`、`Host`、`Origin` など、ブラウザが書き換えを禁じているヘッダーの指定

### 自動化
- 送信前・受信後のスクリプト
- レスポンスの値を変数に取り込んで次のリクエストに使う（ログイン → トークン取得 → API呼び出しの連鎖）
- CSVなどのデータを使った繰り返し実行
- コマンドラインからの実行、CIへの組み込み
- 定期実行と監視

### アサーション
- 正規表現、JSONスキーマでの検証
- 配列の全要素や条件付き抽出を表すJSONパス（`data.items[0].id` のような単純なパスだけ使える）
- 自由に書けるテストコード

### 変数
- グローバル変数、システム単位の変数（環境単位だけ）
- 乱数、現在時刻、UUIDなどの動的な値
- 値を画面上で隠す秘密の変数

### 整理と共有
- 分類の折りたたみ、並べ替え、リクエストの複製、環境ごとに違うリクエスト一覧を持つこと
- チームでの共有と同期（JSONファイルの受け渡しだけ）
- Postmanコレクション、OpenAPI（Swagger）、cURL、HARのインポート
- cURL以外のコード生成（JavaScript、Pythonなど）
- モックサーバー、APIドキュメントの生成

### レスポンス表示
- シンタックスハイライト、ボディ内の検索、折りたたみ
- HTML・XMLのプレビュー、ファイルとして保存
- DNS・接続・TLSなど、応答時間の内訳
- 履歴からの過去レスポンスの再表示

### エビデンス
- PDFでの出力（HTMLレポートをブラウザで印刷すれば作れる）
- Excelへの画像レスポンスの貼り付け、ボディの1行が1,000文字を超える場合の1セル表示（複数行に分けて出力する）
- ボディ内の機密情報の伏せ字（ヘッダーだけ対象）
- 画面キャプチャの添付

### その他
- 日本語以外の画面表示
- Chrome以外での動作（デスクトップアプリ版、VS Code版はない）

## 開発時の読み込み
パッケージ管理は [pnpm](https://pnpm.io/) を使う。

1. `pnpm install` を実行する（同梱ライブラリが `vendor/` にコピーされる。これをしないとExcel出力が動かない）
2. `chrome://extensions` を開き「デベロッパーモード」をオンにする
3. 「パッケージ化されていない拡張機能を読み込む」でこのフォルダを選ぶ
4. コードを変更したら、拡張機能カードの更新ボタンを押して画面を再読み込みする

## 構成
| ファイル | 役割 |
| --- | --- |
| `manifest.json` | 拡張機能の定義（権限、バージョン） |
| `background.js` | アイコンクリックで画面をタブで開く |
| `app.html` / `app.css` / `app.js` | 画面本体 |
| `core.js` | 画面に依存しない処理（URLの組み立て、アサーション、インポート、レポート生成）。`app.js` より先に読み込む |
| `test/` | 共通処理と一括実行のテスト |
| `icons/` | アイコン |
| `vendor/` | 同梱ライブラリ。`pnpm install` で生成され、Gitには入れない |
| `docs/` | インポートファイルの書式と見本 |
| `scripts/vendor.mjs` | `node_modules` から `vendor/` へライブラリをコピーする |

## テスト
```
pnpm test
```
`core.js` の処理を Node.js 標準のテスト機能で確かめる（追加のライブラリなし）。一括実行の順序・中止・エビデンス保存も検証する。対象は、URLの組み立て、アサーションの判定、インポートの読み込みと旧形式の変換、HTML・Excelレポートの生成。

画面の操作（クリックや表示）は対象外。画面を変えたときは、Chromeに読み込んで手で確かめる。

処理を足すときは、画面に触れない部分を `core.js` に書き、`test/core.test.js` にテストを足す。

## データの扱い
- 保存先は `chrome.storage.local`（そのPCのブラウザ内）のみ
- 送信先はユーザーが指定したAPIだけで、それ以外への通信は行わない
- エビデンス出力の伏せ字はヘッダーのみ対象。ボディ内の機密情報はそのまま出力される

## リリース

ストア掲載文・権限説明・公開手順は [Chrome Web Store 公開ガイド](docs/publishing/chrome-web-store.md) を参照。公開用の [プライバシーポリシー](docs/publishing/privacy-policy.md) も用意している。運営者・問い合わせ先の設定と、ポリシーのHTTPS公開は提出前に必要。

1. `manifest.json` の `version` を上げる（`package.json` の `version` も合わせる）
2. `pnpm zip` を実行する（ライブラリの同梱、構文チェック、テストの後、`dist/evirest-<version>.zip` を作成）
3. できたZIPをChromeウェブストアにアップロードする

`pnpm check` だけ実行すると、JSの構文と `manifest.json` の形式を確認できる。
