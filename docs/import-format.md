# インポートファイルの書式

EviREST の「インポート」で読み込めるJSONファイルの書式。
AI（Claude など）や手作業でこのファイルを作れば、URL・クエリ・ヘッダー・ボディ・アサーションを入力済みのリクエストをまとめて取り込める。

- 取り込み方: EviREST の画面左下「インポート」を押し、ファイルを選ぶか、JSONを貼り付けて「取り込む」を押す。AIの回答をコードブロックごと貼り付けてもよい
- `id` が同じものは**更新**、`id` がない（または新しい）ものは**追加**される。削除はしない。詳しくは下の「id と更新」を参照
- 完全な例: [import-sample.json](import-sample.json)
- EviREST の画面左下「プロンプトを表示」を押すと、この書式をAIに伝えるプロンプトを表示し、編集してコピーできる（中身は `core.js` の `AI_PROMPT`。書式を変えたら両方を直す）

## AIへの頼み方の例

> `docs/import-format.md` の書式で、`openapi.yaml` の全エンドポイントを EviREST のインポートファイルにして。
> システム名は「顧客管理」、環境はローカル（`http://localhost` のポート8080）と検証（`https://stg.example.com`）を作って。
> URLはパスだけ書き、トークンは `${token}` にして、各リクエストにステータスコードのアサーションを付けて。

## 全体

画面の階層は「システム ＞ 環境 ＞ パッケージ ＞ サブパッケージ ＞ リクエスト」。JSONの `requests` は平らな配列にし、各リクエストに分類名を書く。リクエストはシステムに1回だけ書き、そのシステムのすべての環境で共有される。

```json
{
  "app": "evirest",
  "version": 2,
  "systems": [
    {
      "id": "crm",
      "name": "システム名",
      "envs": [{ "id": "stg", "name": "環境名", "baseUrl": "https://api.example.com", "port": "8443", "vars": [{ "k": "変数名", "v": "値" }] }],
      "requests": [ ... ]
    }
  ]
}
```

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| `app` | ○ | `"evirest"` 固定 |
| `version` | | `2` |
| `systems` | ○ | システムの配列 |
| `systems[].id` | | システムの `id`。下の「id と更新」を参照 |
| `systems[].name` | | システム名 |
| `systems[].envs` | | 環境の配列。下の「環境」を参照 |
| `systems[].requests` | | リクエストの配列。下の「リクエスト」を参照 |

旧形式（`collections` と全体共通の `envs` を持つ `version: 1`）も読み込める。その場合、コレクションがシステムになり、環境は各システムに複製される。

## id と更新

システム・環境・リクエストには `id`（文字列）を付けられる。取り込むとき、次のように突き合わせる。

| 対象 | 突き合わせる範囲 | 同じ `id` があるとき | ないとき |
| --- | --- | --- | --- |
| システム | 全体 | 名前を更新し、中の環境とリクエストを下の規則で取り込む | 新しいシステムとして追加 |
| 環境 | 同じシステムの中 | 書かれている項目（`name` `baseUrl` `port` `color`）だけ上書き。変数は名前で突き合わせて追加・更新する | そのシステムに追加 |
| リクエスト | 同じシステムの中 | 丸ごと置き換える（書かなかった項目は初期値に戻る） | そのシステムに追加 |

- `id` を書かなかったものは、毎回新しく追加される（同じファイルを2回取り込むと2つできる）
- JSONに書かれていないシステム・環境・リクエストは、そのまま残る（削除はされない）
- 環境の変数は、値が空（`"v": ""`）なら既存の値を残す。画面で入れたトークンなどが、取り込みで消えないようにするため
- 「エクスポート」で書き出したJSONには `id` が入っている。それを編集して取り込めば、既存のものを更新できる
- 自分で `id` を付けるときは、半角英数字とハイフンで分かりやすい名前にする（例: `crm` / `stg` / `users-list`）

## 環境（`systems[].envs[]`）

| 項目 | 省略時 | 内容 |
| --- | --- | --- |
| `id` | 自動で採番 | 環境の `id`。同じシステムの中で重複させない |
| `name` | `"環境"` | 環境名（例: ローカル、検証、本番） |
| `baseUrl` | 空 | 送信先のドメイン（例: `https://stg.example.com`）。`/v1` のような共通のパスを含めてもよい |
| `port` | なし | ポート番号。**文字列**で書く（`"8080"`）。`baseUrl` のホスト名の後ろに付く |
| `color` | 標準色 | `"#2563eb"` のような6桁の色。空文字で標準色に戻る。不正な値も標準色になる |
| `vars` | なし | 変数。`{ "k": "変数名", "v": "値" }` の配列 |

## リクエスト（`systems[].requests[]`）

| 項目 | 省略時 | 内容 |
| --- | --- | --- |
| `id` | 自動で採番 | リクエストの `id`。同じシステムの中で重複させない |
| `name` | URLを表示 | 一覧に出る名前 |
| `package` | 空 | パッケージ名。空なら「未分類」に表示 |
| `subpackage` | 空 | パッケージ内のサブパッケージ名。空ならパッケージ直下に表示 |
| `batchSelected` | `false` | 一括実行の対象か。真偽値で書く。実行した結果はすべてエビデンスに保存する |
| `params` | URLから取得 | クエリの名前・値。`url` に `?page=${page}` と書く場合は、ここに `{ "k": "page", "v": "2" }` を指定する |
| `pathParams` | なし | パスパラメータの名前・値。下の例を参照 |
| `method` | `"GET"` | `GET` `POST` `PUT` `PATCH` `DELETE` `HEAD` `OPTIONS` `QUERY` のどれか（大文字） |
| `url` | 空 | ドメインを除いたパス（例: `/users?page=2&limit=20`）。送信先は選択中の環境の `baseUrl` になる。クエリはここに含めて書くと、取り込み時にクエリ欄へ自動で展開される |
| `headers` | なし | `{ "k": "名前", "v": "値" }` の配列 |
| `bodyType` | `"none"` | `none` `json` `text` `form` のどれか |
| `body` | 空 | `bodyType` が `json` か `text` のときの本文。**文字列**で書く（JSONもオブジェクトではなく文字列にする） |
| `form` | なし | `bodyType` が `form` のときの項目。`{ "k": "名前", "v": "値" }` の配列 |
| `auth` | 認証なし | 下の「認証」を参照 |
| `asserts` | なし | 下の「アサーション」を参照 |

補足:
- `url` を `https://` などから書いた場合は、環境の `baseUrl` を使わずそのURLに送信する。環境を切り替えても送信先が変わらなくなるので、通常はパスだけ書く
- `GET` と `HEAD` ではボディは送信されない
- `Content-Type` は `bodyType` に合わせて自動で付く。`headers` に書いた場合はそちらが優先される
- `params`・`pathParams`・`headers`・`form`・`vars` の各行に `"on": false` を付けると、無効な行として取り込まれる

## 分類・パラメータ・エビデンスの例

```json
{
  "id": "tenant-users-list",
  "name": "テナントのユーザー一覧",
  "package": "ユーザー",
  "subpackage": "一覧",
  "batchSelected": true,
  "method": "GET",
  "url": "/tenants/${tenantId}/users?page=${page}",
  "pathParams": [{ "k": "tenantId", "v": "demo-tenant" }],
  "params": [{ "k": "page", "v": "2" }],
  "asserts": [{ "target": "status", "op": "eq", "value": "200" }]
}
```

入力欄には `/tenants/${tenantId}/users?page=${page}` を残し、送信予定URLには展開した `/tenants/demo-tenant/users?page=2` を表示する。結果欄の「送信URL」は送信した時点の値を表示する。

パスの `${tenantId}` は `pathParams` の値を優先する。行が空欄または無効なら環境変数 `tenantId` を使う。`{tenantId}` の記法も使えるが、こちらは `pathParams` の値が必要。パス欄の値はURLエンコードする。値に `${変数名}` を書いて環境変数を使うこともできる。

クエリは従来の `/users?page=2` でも取り込める。画面では `?page=${page}` に整理し、具体的な値をクエリ欄に保持する。テンプレート形式を再インポートするときは `params` も含める。行の `v` は文字列で書く。

`package` と `subpackage` はシステム内の分類で、全環境で共有する。既存リクエストを更新するときに分類や `batchSelected` を省略すると初期値に戻るので、保持したい値も書く。

`batchSelected: true` はサイドメニューの一括実行対象チェックをオンにする。チェックしたリクエストだけを実行し、その結果はすべて「エビデンス」タブに保存する。一括実行結果タブのHTML・Excelレポートも、今回実行した全件を対象とする。旧項目 `recordEvidence` も読み込める。`batchSelected` がなければ、そのチェック状態を引き継ぐ。

## 認証（`auth`）

```json
{ "type": "bearer", "token": "${token}" }
{ "type": "basic", "user": "admin", "pass": "${password}" }
```

`type` は `none` `basic` `bearer` のどれか。APIキーなど他の方式は `headers` に直接書く。

「ブラウザのCookieを送る」の設定は取り込まない。ファイルに `"cookies": true` があっても、インポートしたリクエストはCookieを送らない設定になる。必要なら画面の「認証」タブでオンにする。

## アサーション（`asserts[]`）

```json
{ "target": "json", "path": "data.items[0].id", "op": "eq", "value": "123" }
```

| `target` | 検証する対象 | `path` |
| --- | --- | --- |
| `status` | ステータスコード | 不要 |
| `header` | レスポンスヘッダーの値 | ヘッダー名（例: `content-type`） |
| `body` | レスポンスボディ全体（テキスト） | 不要 |
| `json` | レスポンスJSONの中の値 | パス（例: `data.items[0].id`） |
| `time` | 応答時間（ミリ秒） | 不要 |

| `op` | 意味 | `value` |
| --- | --- | --- |
| `eq` | 等しい | 期待値 |
| `ne` | 等しくない | 期待値 |
| `contains` | 含む | 含まれるべき文字列 |
| `exists` | 存在する | 不要 |
| `lt` | より小さい | 数値 |
| `gt` | より大きい | 数値 |

- `value` は数値でも**文字列**で書く（`"200"`）
- `json` のパスは `a.b[0].c` の形だけ使える。ワイルドカードや条件式は使えない

## 環境変数

`${変数名}` と書いた箇所は、送信時に選択中の環境の値に置き換わる。
使える場所は、URL、ヘッダー、ボディ、フォーム、認証、アサーションの期待値（`value`）。

トークンやパスワードなどの秘密の値は、ファイルには書かず変数にしておき、取り込んだあと画面の「環境変数」で値を入れる。
